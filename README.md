# Solar System Sim

An interactive N-body simulation of the Solar System, rendered with Three.js and driven by a physics engine written in C and compiled to WebAssembly with Emscripten. [Live demo](https://gnardisitor.github.io/solar-system-sim/)

## Features

- N-body gravity for the Sun and all eight planets, computed in C and compiled to WebAssembly rather than run in JavaScript.
- Three integrators to pick from: Euler, position Verlet, and Runge-Kutta, each with different accuracy and step-size tradeoffs.
- Initial position and velocity vectors for any year from 1750 to 2050, pulled from JPL Horizons and cached locally so switching years is instant.
- Adjustable step size and update rate.
- Three.js rendering: textured bodies, orbit trails, a starfield background, and orbit controls for the camera.

## Tech stack

| Layer | Tool |
|---|---|
| Physics engine | C, compiled to WebAssembly with [Emscripten](https://emscripten.org/) |
| Rendering | [Three.js](https://threejs.org/) |
| App shell | Vanilla TypeScript, no framework |
| Build | [Vite](https://vite.dev/) |
| Ephemeris data | [JPL Horizons](https://ssd.jpl.nasa.gov/horizons/), pre-fetched by a small C/libcurl tool and cached as JSON |
| Textures | [Solar System Scope](https://www.solarsystemscope.com/textures/) |
| Deployment | GitHub Pages, via GitHub Actions |

## Getting started

### Prerequisites

- [Node.js](https://nodejs.org/) `^20.19.0` or `>=22.12.0`
- [Emscripten](https://emscripten.org/docs/getting_started/downloads.html) (`emcc` on your `PATH`). Needed only if you're editing `src/nbody.c`; the compiled `src/nbody.wasm`/`src/nbody.js` are already checked in.

### Setup

```bash
npm install
npm run dev
```

### Production build

```bash
npm run build   # type-checks with tsc, then builds with Vite
npm run preview # serve the production build locally
```

### Recompiling the physics engine

If you change `src/nbody.c`, recompile it with the same flags used in CI (`.github/workflows/deploy.yaml`):

```bash
emcc src/nbody.c -o src/nbody.js -O3 \
  -s EXPORTED_FUNCTIONS=_init_body,_init_system,_simulate_step,_simulate_all,_get_x,_get_y,_get_z,_free_all \
  -s EXPORTED_RUNTIME_METHODS=cwrap \
  -s MODULARIZE=1 -s EXPORT_ES6=1 -s ENVIRONMENT=web
```

```
├── index.html                    # simulation (root page)
├── about.html                    # info / documentation page
├── src/
│   ├── main.ts                   # entry point, wires physics, scene, and controls together
│   ├── scene.ts                  # Three.js scene, camera, lighting, meshes
│   ├── physics.ts                # thin TypeScript wrapper around the compiled WASM module
│   ├── controlsPanel.ts          # dock UI logic

│   └── nbody.wasm, nbody.js      # compiled output of nbody.c, checked in (see above)
├── extra/
│   └── api.c                     # standalone tool that fetches JPL Horizons vectors into api.json
├── public/
│   ├── api.json                  # pre-cached ephemeris data for 1750-2050
│   ├── documentation.md          # project history and the physics/math behind each integrator
│   └── textures/, fonts/, icons/, css/
└── .github/workflows/deploy.yaml # builds and deploys to GitHub Pages on push to main
```

## Regenerating the ephemeris cache

`public/api.json` holds the initial position and velocity vectors for every year from 1750 to 2050. It's generated by the standalone tool in `extra/`, which queries the JPL Horizons API directly (requires `libcurl`, e.g. `libcurl4-openssl-dev` on Debian/Ubuntu):

```bash
cd extra
gcc api.c -o api -lcurl
./api 1750 2050 # writes to extra/api.json
cp api.json ../public/api.json
```

Only needed if you want to extend the year range or refresh the cached data. The repo already ships with `public/api.json` populated.

## Deployment

Pushing to `main` triggers `.github/workflows/deploy.yaml`, which compiles `nbody.c` to WebAssembly, builds the site with Vite, and publishes to GitHub Pages.

## Background

This started as a Python class project, got ported to C for speed, and eventually moved to the web via Emscripten and Three.js. For the full story and the math behind the Euler, Verlet, and RK4 integrators, see [`public/documentation.md`](public/documentation.md), or open the About page from the running app.
